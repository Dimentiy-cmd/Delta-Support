## [1.2.0] - 2026-08-06

### Added — Support API и AI tool calling
- Интеграция с Support API основного сервера: баланс, подписки, ключи клиента по Telegram ID (`modules/user_info.py`)
- AI отвечает по реальным данным аккаунта клиента вместо общих фраз — данные попадают в системный промпт (`{account_info}`)
- AI tool calling: read-only инструменты (проверка платежа, инфо о подписке/устройствах) AI вызывает автономно, с обязательной серверной проверкой владения (`find_own_subscription`) — не доверяет параметрам, которые мог подставить AI/промпт-инъекция
- Разрушающие действия (сброс устройств, перевыпуск подписки) не выполняются напрямую — AI формирует предложение, реальный вызов происходит только после подтверждения клиента кнопкой в Telegram (`PendingAction`), с повторной проверкой владения в момент клика
- Полная спецификация Support API для тех, кто реализует свой сервер — [docs/SUPPORT_API_SPEC.md](docs/SUPPORT_API_SPEC.md)
- Лёгкий RAG-отбор базы знаний под конкретный вопрос (лексический скоринг с грубым стеммингом по префиксу) — включается автоматически при росте базы, без embeddings и векторной БД

### Added — AI: голос, фото, провайдеры
- Распознавание голосовых сообщений клиента через Whisper (Groq)
- Разбор фото и скриншотов ошибок vision-моделями
- Несколько AI-провайдеров одновременно (Groq, OpenAI-совместимые) с приоритетом и автопереключением при лимитах/ошибках, несколько ключей на провайдера

### Added — автоматизация
- Автозакрытие неактивных чатов: напоминание клиенту, затем закрытие, если ответа не последовало
- SLA-пинг: повторное уведомление штата, если запрос менеджера никто не взял в работу
- Еженедельный отчёт админам в Telegram (метрики + AI-темы обращений)
- Команды менеджера в топике группы: `/info`, `/summary`, `/ai on|off`, `/note`, `/ban`/`/unban`
- Кнопки «🙋 Взять в работу» и «👤 Инфо» при эскалации
- Авто-назначение менеджера, если он отвечает клиенту, не нажав «Взять в работу»

### Added — веб-панель
- Канбан-доска чатов за сегодня/неделю/месяц с кратким описанием проблемы
- Дашборд: доля решённых AI, среднее время реакции менеджера, топ обращений, нагрузка по часам, AI-темы недели
- Карточка аккаунта клиента (баланс/подписки/ключи) прямо в окне чата
- AI-подсказка ответа менеджеру и сохранение решённого диалога в базу знаний одной кнопкой
- Поиск по Telegram ID, счётчики на фильтрах, фильтр «Мои чаты»
- Экспорт/импорт настроек панели единым JSON (без чатов)
- Мобильная адаптация панели
- Звуковое уведомление на новую эскалацию/сообщение клиента — вкл/выкл одной кнопкой в шапке
- WebSocket-соединение переподключается само при обрыве, с ресинком состояния

### Added — настраиваемость
- Текст и режим показа сообщений менеджера клиенту: одним сообщением с префиксом либо разовый заголовок сессии + ответы (reply) на него
- `create_admin.py` теперь умеет сбрасывать пароль существующего пользователя, а не только создавать нового

### Changed
- `install.sh` перенесён в корень репозитория — команда `curl -sSL .../main/install.sh | bash` из README теперь реально работает (раньше файл лежал в `scripts/` и путь не совпадал)
- README и вся документация в `docs/` переписаны под текущую архитектуру, добавлена благодарность [GOFONCK](https://github.com/GOFONCK) за исходную идею и старт проекта
- `main.py` переведён с deprecated `@app.on_event` на `lifespan` — исправляет неинициализированную БД на новых версиях Starlette
- Зависимости в `requirements.txt` зафиксированы по версиям вместо открытых диапазонов
- Порты PostgreSQL и Redis в `docker-compose.yml` по умолчанию открыты только на `127.0.0.1`

### Fixed
- Чат в списке терял выделение и «слетал» из вида при смене статуса, если он не попадал под текущий фильтр — активный открытый чат теперь всегда остаётся на экране
- Кнопки «Подключиться»/«Завершить» могли зависать, требуя ручного обновления страницы: отправка уведомления клиенту в Telegram блокировала HTTP-ответ панели — при недоступности сети до Telegram эндпоинт мог не отвечать сколько угодно долго. Уведомление клиенту вынесено в фоновую задачу, ответ панели больше не зависит от Telegram
- Повторный клик по «Подключиться»/«Завершить» на чате, уже находящемся в этом статусе, создавал дубликаты системных сообщений и повторные уведомления клиенту — добавлена идемпотентность
- Подтверждение/отмена разрушающего действия (сброс устройств и т.п.) чужим пользователем удаляло токен подтверждения и лишало настоящего владельца возможности подтвердить своё же действие
- Менеджер, подключившийся через веб-панель (`join_chat`), не проставлял `manager_id` — из-за этого SLA-пинг мог повторно дёргать штат, даже когда чат уже был взят в работу
- `close_chat`/`back_to_ai` в веб-панели обновляли статус чата напрямую через ORM, минуя сброс таймеров автозакрытия/SLA — закрытый чат мог сохранять устаревшие `waiting_since`/`reminder_sent_at`
