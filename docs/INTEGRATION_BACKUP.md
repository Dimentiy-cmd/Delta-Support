## Support API: зачем это нужно

Если у вас есть отдельный сервер (например, панель управления самим VPN-сервисом) с API для получения данных о пользователе по его Telegram ID — эта интеграция подключает его к боту поддержки. Клиент пишет «какой у меня баланс» — AI отвечает точной цифрой, а не «проверьте в личном кабинете».

Кроме чтения данных, через этот же API реализованы **действия** (проверка платежа, сброс устройств, перевыпуск подписки) — как AI ими пользуется и какие там защиты от чужих данных, см. отдельно [docs/AI_TOOL_CALLING.md](AI_TOOL_CALLING.md).

## Настройка подключения

| Поле | Описание |
|---|---|
| **Включено** | Общий переключатель интеграции |
| **URL сервера** | Базовый адрес, например `https://example.com` — без `/api/support/...` в конце |
| **Токен** | Bearer-токен вида `sup_...`. В панели показывается замаскированным (`••••xxxx`), реальное значение не отображается повторно |
| **TTL кеша (сек)** | Как долго кешировать данные одного клиента, прежде чем запрашивать заново (по умолчанию 120 сек) |

Ожидаемый контракт Support API — эндпоинт `POST {URL}/api/support/user_info` с телом `{"user_id": <telegram_id>}` и авторизацией `Authorization: Bearer sup_...`, возвращающий баланс, подписки, ключи и последние транзакции. Полная спецификация всех эндпоинтов с примерами запросов/ответов — [docs/SUPPORT_API_SPEC.md](SUPPORT_API_SPEC.md); как AI использует действия (сброс устройств, перевыпуск подписки) — [docs/AI_TOOL_CALLING.md](AI_TOOL_CALLING.md).

## Проверка подключения

Блок «Проверка подключения» на той же странице: вводите Telegram ID реального клиента → «Проверить» → видите **оба** формата сразу:
- Контекст, который получит AI (компактный текст для промпта)
- Карточка, которую увидит менеджер при эскалации

Так можно проверить интеграцию, не отправляя ни одного сообщения в реальный чат.

## Что именно передаётся AI

Компактная сводка, а не сырой JSON: баланс, флаг блокировки, доступность триала, дата регистрации, до 6 активных подписок (тариф, срок, трафик), ключи Outline/Xray, последние 3 платежа и последние 3 действия по балансу. AI явно инструктируется не раскрывать технические ID/short_id без необходимости и не выдумывать данные, которых нет в этом блоке.

## Экспорт настроек

Кнопка «Скачать экспорт» формирует один JSON-файл со всем, что нужно для переноса или бэкапа конфигурации:

- Все настройки из `system_config` (промпты, приветствие, AI контекст, автоматизация, Telegram-топики, Support API URL/токен и т.д.)
- Все статьи базы знаний
- Все AI-провайдеры (включая ключи, если не снят флажок «Включить секреты»)

**Чаты, сообщения и пользователи панели в экспорт не входят.**

Галочка «Включить секреты» — если снять, в файл не попадут API-ключи провайдеров и токен Support API (например, для передачи файла кому-то, кому не нужно видеть секреты).

## Импорт настроек

Загрузите файл экспорта и выберите режим:

- **Слияние (merge)** — обновляет существующие настройки, дополняет базу знаний и провайдеров, ничего не удаляет. Статьи и провайдеры с совпадающим заголовком/именем — обновляются, новые — добавляются
- **Полная замена (replace)** — база знаний и AI-провайдеры **полностью заменяются** содержимым файла; `system_config` в любом режиме только обновляется (без удаления существующих ключей)

После импорта кеш AI и Support API сбрасывается автоматически — новые настройки применяются сразу, без перезапуска бота.

## Что НЕ входит в экспорт

- История чатов и сообщений
- Учётные записи админов/менеджеров и их пароли
- Загруженные файлы брендинга (логотип и т.п.)

Для полного бэкапа (включая историю переписки) используйте `pg_dump` — см. раздел «Резервное копирование» в [README.md](../README.md#резервное-копирование).
