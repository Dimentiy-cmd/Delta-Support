## Как работает fallback между провайдерами

При каждом сообщении клиента бот перебирает **активных** провайдеров по возрастанию `priority` (меньше — раньше). Как только один ответил успешно — остальные не трогаются. Если провайдер вернул ошибку (лимит, невалидный ключ, таймаут) — бот молча пробует следующего по списку.

Типичная настройка: сильная модель с приоритетом 10 (для качества), резервная с большими дневными лимитами — приоритетом 20, ещё одна на крайний случай — 30.

## Поддерживаемые типы

| Тип | Base URL по умолчанию |
|---|---|
| `groq` | `https://api.groq.com/openai/v1` |
| `openai` | `https://api.openai.com/v1` |
| `anthropic` | `https://api.anthropic.com/v1` |
| `gemini` | `https://generativelanguage.googleapis.com/v1beta` |
| `deepseek` | `https://api.deepseek.com/v1` |
| `mistral` | `https://api.mistral.ai/v1` |
| `openrouter` | `https://openrouter.ai/api/v1` |

Запросы уходят в формате OpenAI Chat Completions (`/chat/completions`), поэтому реально работают провайдеры с OpenAI-совместимым API — это все из списка выше, кроме нюансов у Anthropic/Gemini (у них своя схема API, для них может потребоваться прокси-совместимость на стороне base_url).

## Поля провайдера

| Поле | Описание |
|---|---|
| **Название** | Просто для себя, чтобы отличать записи в списке |
| **Тип** | Один из типов выше — определяет base URL по умолчанию |
| **API ключ** | Основной ключ, в списке отображается замаскированным (`gsk_ab***wxyz`) |
| **Base URL** | Можно переопределить (например, свой прокси или self-hosted совместимый API) |
| **Модель** | Точное имя модели у провайдера, например `llama-3.3-70b-versatile` |
| **Активен** | Выключенные провайдеры пропускаются при переборе |
| **Приоритет** | Чем меньше число — тем раньше пробуется |
| **Лимит запросов/мин** | Информационное поле, не влияет на реальное троттлирование бота |

## Несколько ключей на одного провайдера

Если у вас несколько API-ключей одного провайдера (например, несколько бесплатных Groq-аккаунтов) — добавьте их через поле дополнительных ключей. Бот случайным образом выбирает один из всех доступных ключей провайдера при каждом запросе — это балансировка нагрузки между ключами одного и того же провайдера, отдельно от fallback между разными провайдерами.

## Vision-модели: распознавание фото

Когда клиент присылает фото (скриншот ошибки, экрана приложения) и в настройках [Автоматизации](AUTOMATION.md) включён разбор изображений — бот ищет среди активных провайдеров модель, поддерживающую изображения. Определяется по имени модели — подходят модели, содержащие в названии:

```
llama-4, scout, maverick, vision, gpt-4, gpt-5, gemini, claude, qwen-vl, qwen3.6, pixtral
```

Например, `qwen/qwen3.6-27b` на Groq. Если ни один активный провайдер не подходит — бот сообщит клиенту, что нужно описать проблему текстом или подключить менеджера.

**Важно:** модели на базе Qwen3 на Groq по умолчанию возвращают внутренний `<think>...</think>` блок рассуждений — бот автоматически включает `reasoning_format: hidden` и подчищает такие блоки на всякий случай, так что в ответе клиенту его не видно.

## Голосовые сообщения (Whisper)

Расшифровка голосовых идёт отдельным вызовом к `https://api.groq.com/openai/v1/audio/transcriptions` (модель `whisper-large-v3-turbo`, с fallback на `whisper-large-v3`), используя ключ первого активного Groq-провайдера из списка. Если ни одного Groq-провайдера нет — расшифровка недоступна, даже если настроен, например, только OpenAI.

## Проверка ключа

Кнопка «Проверить» на странице отправляет тестовый запрос («Привет! Просто тестирую соединение...») с указанными ключом/base URL/моделью — не сохраняя ничего, просто чтобы убедиться, что ключ рабочий, прежде чем добавлять провайдера.

## Актуальность моделей Groq

Groq периодически снимает с публикации старые модели (например, `llama-4-scout` был доступен, а потом пропал из списка). Если провайдер начал стабильно падать с `model_not_found` (404) — проверьте актуальный список:

```bash
curl -H "Authorization: Bearer YOUR_GROQ_KEY" https://api.groq.com/openai/v1/models
```

и обновите поле «Модель» на странице.
