## Информация о проекте

- **Название проекта** — используется в приветствии, системном промпте AI (`{project_name}`) и в брендинге панели
- **Описание проекта** — короткое описание сервиса, попадает в контекст AI
- **Сайт**, **Ссылка на бота** — отображаются клиентам в сообщениях, где это уместно

## Приветственное сообщение

Текст, который бот отправляет по команде `/start`. Поддерживает плейсхолдеры:

| Плейсхолдер | Что подставляется |
|---|---|
| `{first_name}` | Имя пользователя Telegram |
| `{project_name}` | Название проекта |
| `{project_description}` | Описание проекта |

Пример:
```
👋 Здравствуйте, {first_name}!

Я бот поддержки {project_name}.
Помогу с подключением, оплатой, подписками и настройкой на любых устройствах.

Просто напишите ваш вопрос — отвечу за пару секунд.
```

Если поле пустое — используется дефолтный шаблон из кода.

## Сообщения менеджера клиенту

Когда менеджер отвечает клиенту (из веб-панели или из топика группы), клиент должен понимать, что дальше отвечает не бот, а человек. За это отвечают два поля:

- **Текст перед сообщением менеджера** — по умолчанию `👨‍💼 Менеджер поддержки`, можно заменить на что угодно (например `👤 Поддержка Delta VPN`)
- **Режим показа** — два варианта:

| Режим | Как выглядит у клиента |
|---|---|
| **Одним сообщением** (по умолчанию) | Каждое сообщение менеджера приходит одним сообщением: `«👨‍💼 Менеджер поддержки»` и текст ответа вместе, одним блоком |
| **Заголовок один раз за сессию** | При первом ответе менеджера в диалоге отдельно приходит сообщение-заголовок; все последующие сообщения менеджера в рамках этой же сессии идут **ответом (reply)** на него, без повторения заголовка |

«Сессия» здесь — это период с момента, когда менеджер подключился к чату, до его закрытия или возврата к AI. Как только сессия заканчивается (клиент возвращается к AI или чат закрывается), заголовок сбрасывается — при следующей эскалации отправится заново.

**Исключение:** видео-кружки (`video_note`) и стикеры не поддерживают подпись (caption) в Telegram API — в режиме «Одним сообщением» для них префикс всё равно уходит отдельным текстовым сообщением перед самим видео/стикером; в режиме «Заголовок один раз за сессию» это исключение не требуется, так как заголовок и так отдельное сообщение.

## Системный промпт: как устроен

Промпт по умолчанию задаёт AI роль «сотрудника поддержки», а не абстрактного ассистента: без приветствия в каждом сообщении, без выдумывания фактов, с явной эскалацией на менеджера при нехватке данных.

Если вы пишете свой промпт — доступны плейсхолдеры:

| Плейсхолдер | Содержимое |
|---|---|
| `{project_name}` | Название проекта |
| `{user_context}` | Имя/username/Telegram ID текущего клиента |
| `{account_info}` | Данные аккаунта клиента из Support API: баланс, подписки, ключи (см. [docs/INTEGRATION_BACKUP.md](INTEGRATION_BACKUP.md)) |
| `{service_context}` | Описание сервиса, FAQ, тарифы, инструкции и релевантные статьи базы знаний (см. [docs/AI_CONTEXT.md](AI_CONTEXT.md)) |

Если в вашем кастомном промпте нет плейсхолдера `{account_info}` — данные аккаунта всё равно допишутся в конец промпта автоматически, чтобы AI никогда не отвечал про баланс/подписку вслепую.

**Хорошая практика:** не удаляйте инструкцию про эскалацию («если не можешь решить — предложи менеджера, напиши слово "менеджер"») — по этому слову-триггеру клиенту показывается кнопка приглашения менеджера.

## Приоритет: панель vs `.env`

Все поля этой страницы хранятся в базе (`system_config`) и имеют приоритет над одноимёнными переменными `.env` (`PROJECT_NAME`, `AI_SUPPORT_ENABLED` и т.д.). Переменные окружения используются только как значение по умолчанию при первом запуске на пустой базе — после того как вы сохранили что-то в панели, `.env` для этих полей больше не читается.
